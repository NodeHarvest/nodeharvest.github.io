# NodeHarvest 产品状态与执行计划

> 更新日期：2026-07-26<br>
> 当前版本：0.1.0<br>
> 当前阶段：可靠 Scan 基座建设（诊断与安全降级首版已完成）

## 一句话状态

NodeHarvest 已经具备可运行的本地能力发现基座：用户只安装 NodeHarvest，即可自动接入经过校验的扫描能力，盘点本机的 Skill、MCP、Plugin、Hook 和 Agent-first CLI。

当前产品还不是完整 MVP。Scan 的基础闭环、结构化诊断和最后成功结果降级首版已经形成；安装回滚与跨平台验收仍需补齐，经验沉淀 Harvest 与动态匹配 Invoke 尚未进入功能实现。

## 用户现在能完成什么

### 单一安装入口

用户不需要单独安装或理解 HarnessKit。首次扫描时，NodeHarvest 会优先使用兼容环境；没有兼容版本时，自动下载并校验固定版本。

### 盘点本地能力

NodeHarvest 能发现本机的 Skill、MCP、Plugin、Hook 和 Agent-first CLI，支持按能力类型、Agent 和 Pack 筛选，并提供适合 Agent 消费的结构化结果。

### 检查并理解运行状态

用户可以判断扫描 provider 当前是可用、不可用、不兼容还是损坏，并获得来源、版本、稳定错误代码和恢复建议。没有发现能力时返回有效空结果，不会误报为系统故障。

### 临时失败时安全降级

成功扫描后，NodeHarvest 会保存最后成功结果。后续扫描临时失败时，有可信历史结果则明确标为“过期快照”并附失败原因；没有可信结果则返回不可用。旧数据不会被冒充为本次扫描结果。

### 安全准备扫描能力

自动准备过程使用固定版本、SHA-256 完整性校验和原子安装，不修改 shell 配置，也不覆盖系统已有兼容工具。校验失败的文件不会被使用。

## 产品完成度

| 产品模块 | 当前状态 | 用户价值 |
|---|---|---|
| Scan 基础扫描 | 已形成可运行闭环 | 能盘点本地 Agent 能力 |
| Scan 无感准备 | 首版已实现 | 无需单独安装 HarnessKit |
| Scan 诊断与安全降级 | 首版已实现 | 能区分最新、过期和不可用结果 |

| Invoke 动态匹配 | 尚未实现 | 暂不能按任务和历史经验推荐能力 |
| 受控能力管理 | 尚未开放 | 暂不自动安装、启停或删除扩展 |

## 已验证结果

- 构建通过；
- 自动化测试 8 项全部通过；
- provider 状态、来源、错误代码与恢复建议验证通过；
- 最后成功扫描快照与失败后过期降级验证通过；
- 发布包内容检查通过；
- Linux x64 完成官方扫描工具真实下载、摘要校验、诊断和扫描闭环；
- 未知数据契约、错误摘要和不支持平台均会被拒绝；
- 多平台资产解析已覆盖 macOS arm64/x64、Linux arm64/x64 和 Windows x64，但除 Linux x64 外仍需真实运行验收。

## 当前用户风险

### 安装失败保护与回滚仍待补齐

扫描临时失败已有明确降级，但 provider 并发安装保护、损坏文件隔离、已验证版本保留和回滚仍未完成。下一批将确保下载或升级失败不会影响已有可用版本。

### 还不能沉淀使用经验

当前只能回答“有哪些能力”，还不能回答“什么任务应该使用哪个 Skill、为什么、效果如何、下次是否继续使用”。

### 还没有动态推荐闭环

当前尚未把本地能力与历史经验联合起来，因此不能完成“描述任务 → 推荐能力 → 解释依据 → 回流结果”。

## 下一阶段计划

### 阶段一：让 Scan 稳定可依赖

交付目标：首次扫描无感完成；断网、损坏、版本不兼容和扫描失败都有明确状态；存在可信历史结果时可安全降级。

主要交付：

已完成首版：

1. provider 状态和结构化诊断；
2. 最后成功扫描快照；
3. 数据“最新、过期、不可用”行为。

下一批：

1. 安装锁、失败清理、版本保留与回滚；
2. 许可证和来源信息随 provider 落盘；
3. macOS、Linux、Windows 真实平台验证。

验收信号：扫描层故障不会让上层误用错误或陈旧数据，也不会破坏已验证版本。

### 阶段二：形成最小 Skill Flow

交付目标：用户可以复盘“做了什么、用了什么 Skill、为什么、结果如何、留下什么经验”。

主要交付：

1. Work、Skill、Result/Experience 三类节点；
2. 简洁 Markdown 与可版本化 JSON；
3. 来源、缺失信息、置信度和人工修订；
4. 使用 2–3 个真实已结束项目验证提取质量。

验收信号：真实项目可以以较低修订成本形成有用、可复用的 Skill Flow。

### 阶段三：建立最小动态匹配闭环

交付目标：用户描述任务后，NodeHarvest 结合本地能力和历史经验给出候选 Skill、推荐理由与历史证据，并把使用结果继续沉淀。

验收信号：完成“任务 → 推荐 → 使用 → 结果 → 新经验”的端到端演示。

### 阶段四：受控能力管理

完成核心闭环后，再开放安装、启停、删除、审计和跨 Agent 部署。所有高影响操作必须具备影响预览、明确确认、执行验证、回滚和审计记录。

## 执行与决策边界

工程、安全、合规、可靠性、兼容性、测试、发布、维护等有标准答案的问题由执行者直接处理；非功能问题和已有共识的产品问题不再提交产品负责人重复决策。

只有涉及产品定位、目标用户、功能范围、用户体验取舍、优先级冲突、已有产品共识变更或真实用户验证推翻产品假设时，才请求产品负责人决策。
